# Savannah-canopy (Self-Healing Application Pipeline)

This project demonstrates the design and implementation of a self-healing application pipeline as a Savannah-canopy online store using modern AI-powered tools and AWS cloud infrastructure.

## 📜 Abstract

The pipeline addresses the persistent challenge of runtime software failures due to bugs, system faults, or misconfigurations. Traditional solutions typically generate alerts without providing contextual insights or fixes. This project introduces a novel, intelligent pipeline that utilizes:

- **AI Agents**
- **Large Language Models (LLMs)**
- **AWS Bedrock**
- **Terraform and AWS infrastructure**

...to detect, analyze, and autonomously attempt to resolve application issues with minimal human intervention.

## 🧠 Features

- Real-time error detection using **AWS CloudWatch**
- Contextual root cause analysis via **AI Agents**
- Code fixes generated by **LLMs via Amazon Bedrock**
- Automated pull requests through **GitHub API**
- Separate pipelines for **testing** and **production** deployments
- Intentional error injection for testing recovery
- Uses structured logging and contextual exception handling

## 🛠️ Technologies

- **Spring Boot** (Java , H2 DB, Swagger, Log4j2)
- **Terraform** for AWS Infrastructure as Code (IaC)
- **Docker + AWS ECS/ECR** for containerization
- **AWS Services**: Lambda, CloudWatch, Bedrock, CodePipeline, CodeBuild
- **GitHub**: Version control, PR management, email notifications
- **Bruno API Client**: API testing

## ⚙️ Pipeline Flow

1. **User triggers an error** in the Spring Boot app (e.g., malformed input).
2. Logs are streamed to **CloudWatch**, filtered for `"ERROR"` events.
3. A **Lambda (AI Agent)** processes the logs and invokes **Amazon Bedrock** with error context and code.
4. The LLM proposes a fix → Lambda raises a **Pull Request**.
5. Developers are **notified via email** to review the PR.
6. If approved, changes are tested in a **test pipeline**, then deployed to **production**.

## 🧪 Testing

Two intentional runtime errors are injected:
- Division by zero in discount calculation
- Null pointer in plant lookup

The pipeline was tested by triggering these errors via Swagger UI and observing:
- CloudWatch Lambda invocation
- Pull request creation
- Test pipeline deployment

## 🤖 AI & LLM Details

- Prompts are designed for LLMs to return JSON-formatted code fixes
- Evaluated models include:
  - `mistral.mistral-7b-instruct-v0:2`
  - `anthropic.claude-3-5-sonnet-20240620-v1:0`
- Output judged based on: correctness, readability, robustness, conciseness, PR quality

## 📈 Results

The system showed strong performance in automatic error resolution, significantly reducing manual debugging and improving system resilience. AI-generated pull requests provided human-readable documentation and required minimal intervention.

## 🚧 Limitations

- Handles one error at a time
- LLM hallucination risk → human review required
- Source code privacy must be handled carefully
- Does not currently support multi-service or distributed applications

## 🔮 Future Work

- Extend support to multi-service architectures
- Improve LLM prompting for complex errors
- Integrate approval automation via test coverage checks
- Replace test pipeline with sandbox testing environments
